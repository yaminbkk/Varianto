# Daily Streak Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox syntax. TDD: failing test first; one commit per step; `npx vitest run`, `npm run build`, `npm run lint` must pass before done.

**Goal:** Count active practice days and show a daily streak, for guests and signed-in users.

**Spec:** `docs/superpowers/specs/2026-11-05-streak-design.md`

## Global Constraints

- `src/domain/` has no React/DOM; domain functions are pure. Day strings are local `YYYY-MM-DD`.
- Storage only through `ProgressStore`; guest makes no network calls; no analytics.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- A streak survives until the end of the next day (alive yesterday, not yet done today). (Task 1)
- Gap of one missed day resets to 0/1. Duplicate and unsorted days are harmless. (Task 1)
- Recording the same day twice does not duplicate it, in both backends. (Task 2, 3)
- A failed `recordActivity` must not make `markLearned`/`saveReview` fail. (Task 4)

### Task 1: Streak domain

Files: `src/domain/learn/streak.ts`, `streak.test.ts`.

- `localDay(date: Date): string` (local calendar date), `streakInfo(days: readonly string[], today: string): { current: number; longest: number; activeToday: boolean }`.
- Tests: empty; only today = 1 active; run ending yesterday keeps `current` with `activeToday=false`; run ending two days ago = 0; missed day splits runs and `longest` is the max run; duplicates/unsorted ok; month and year boundaries (`2026-02-28` → `2026-03-01`).

### Task 2: Store interface and Dexie

Files: `src/storage/progress.ts` (add `recordActivity(day: string): Promise<void>`, `activityDays(): Promise<string[]>`), `src/storage/db.ts` (version 4, table `activity: 'day'`), `src/storage/dexieProgress.ts`, `dexieProgress.test.ts`.

- Tests: empty list; record two days returns both sorted; same day twice stays one; `reset(courseId)` does not erase activity.

### Task 3: Supabase

Files: `supabase/migrations/0002_activity.sql`, `src/storage/supabaseProgress.ts` (gateway `addActivity(day)`, `listActivity()`), `src/storage/supabaseGateways.ts`, `supabaseProgress.test.ts`.

- Tests with the fake gateway: same behaviour as Task 2. Migration: table with primary key `(user_id, day)`, RLS policy like the existing tables, `user_id default auth.uid()`.

### Task 4: Recording and migration

Files: `src/storage/activity.ts` + `activity.test.ts` (`withActivity(store: ProgressStore, now: () => Date): ProgressStore`), `src/app/backends.ts`, `src/storage/migrate.ts` (+ test).

- Tests: each of `markLearned`, `saveReview`, `addDrillResult` records `localDay(now())`; a rejecting `recordActivity` does not reject the call; `copyLocalToAccount` copies days and is idempotent.

### Task 5: UI

Files: `src/ui/StreakBadge.tsx`, `src/ui/AppHeader.tsx`, `src/index.css`; hook `useStreak`.

- Header badge "N-day streak" with text for state ("done today" / "practise today to keep it"); updates after a lesson. Verify in the browser.

### Task 6: Docs and final verification

README feature line, CLAUDE.md status, deploy.md note to run migration 0002; full checks; browser check as guest.

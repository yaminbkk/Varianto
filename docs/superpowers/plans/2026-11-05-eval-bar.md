# Evaluation Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an optional, locally computed Stockfish evaluation bar beside the board on the Learn page and the repertoire board page.

**Architecture:** Pure evaluation logic lives in `src/domain/eval/` (parse UCI scores, map to bar fill and labels, detect finished games). A React-free `src/engine/` layer talks UCI to a Web Worker through a small `EngineTransport` interface (so it is tested with a fake), with a lazy, debounced `Evaluator` on top. The UI is a thin `EvalBar`, `EvalToggle` and `useEvaluation` hook. The engine is the `stockfish` npm package, `lite-single` build, copied unmodified into `public/stockfish/` by a script and loaded only when the bar is on.

**Tech Stack:** TypeScript, React 19, Vite 8, Vitest 5, chess.js 1.4, `stockfish@19.0.1` (GPL-3.0).

**Spec:** `docs/superpowers/specs/2026-11-05-eval-bar-design.md`

## Global Constraints

- `src/domain/` must not import React or the DOM; domain functions are pure.
- Everything in the repo is in English (code, comments, commit messages, UI text).
- Evaluation depth 14, debounce 150 ms, hash 16 MB, `stockfish` pinned to exactly `19.0.1`, build `lite-single` (`stockfish-19-lite-single.js` + `.wasm`).
- Off by default; preference key `varianto.evalbar`; storage failures mean "off".
- No eval on Practice or Drill pages.
- No network request and no engine bytes unless the bar is turned on. No analytics, no new backend.
- Engine files are copied unmodified (the engine finds its wasm by file name), served under `import.meta.env.BASE_URL`.
- Each commit must leave `npx vitest run` and `npm run build` passing, except a commit whose message says `Add failing test for ...`. Commit messages are short, imperative, under 72 characters, and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Before declaring done: `npx vitest run`, `npm run build`, `npm run lint` all pass.

## Review Focus

- Checkmate, stalemate and bare-kings positions give no engine score: show the result, never call the engine. (Task 2, Task 4)
- Black to move: the engine score is from the side to move, so the sign must flip to White's point of view. (Task 1)
- Stepping quickly through moves: only the last position is evaluated, and output from a stopped search never reaches the bar. (Task 3, Task 4)
- Worker or WebAssembly failure: the bar shows an unavailable state, the page keeps working. (Task 3, Task 4)
- `localStorage` blocked or throwing: the preference reads as off and saving does not throw. (Task 6)

### Task 3: Engine session (UCI protocol)

**Files:**

- Create: `src/engine/session.ts`
- Test: `src/engine/session.test.ts`, with a reusable `src/engine/fakeTransport.ts` (test helper, exported for Task 4)

**Interfaces:**

- Consumes: `parseInfoLine` (Task 1), `finalEvaluation` (Task 2), `Evaluation` (Task 1).
- Produces (`session.ts`):
  ```ts
  export interface EngineTransport {
    post(command: string): void
    onMessage(handler: (line: string) => void): void
    onError(handler: (message: string) => void): void
    terminate(): void
  }
  export type EvalUpdate =
    | { status: 'thinking'; evaluation: Evaluation | null }
    | { status: 'done'; evaluation: Evaluation }
    | { status: 'error'; message: string }
  export interface EngineSession {
    /** Supersedes any earlier request; only the latest request's updates are delivered. */
    evaluate(fen: string, onUpdate: (update: EvalUpdate) => void): void
    dispose(): void
  }
  export function createEngineSession(
    transport: EngineTransport,
    options?: { depth?: number; hashMb?: number },
  ): EngineSession // defaults 14 and 16
  ```
- Produces (`fakeTransport.ts`): `class FakeTransport implements EngineTransport` with `sent: string[]`, `terminated: boolean`, `emit(line: string): void`, `fail(message: string): void`.

- [ ] **Step 1: Write the failing tests** (`session.test.ts`, using `FakeTransport`):
  - handshake: creating a session posts `'uci'`; after `emit('uciok')` it posts `'setoption name Hash value 16'` then `'isready'`; an `evaluate` called before `emit('readyok')` posts nothing yet, and after `readyok` posts `'position fen <fen>'` then `'go depth 14'`
  - progress then done: an `info depth 8 ... score cp 20` line gives `{ status: 'thinking', evaluation: { kind: 'cp', value: 20, depth: 8 } }`; `bestmove e2e4` gives `{ status: 'done', evaluation: <the last evaluation> }`; the first update on a new request is `{ status: 'thinking', evaluation: null }`
  - cache: evaluating the same FEN again posts no new `go` and delivers `done` with the cached evaluation immediately
  - supersede: with request A searching, `evaluate(B)` posts `'stop'` and does **not** post `position fen B` until A's `bestmove` arrives; `info` lines emitted for A after the `stop` reach neither callback; after A's `bestmove`, `position fen B` and `go depth 14` are posted; the aborted A result is not cached (evaluating A again later posts a new `go`)
  - finished game: evaluating a checkmate FEN delivers `{ status: 'done', evaluation: { kind: 'final', ... } }` and posts no `go`
  - failure: `transport.fail('boom')` delivers `{ status: 'error', message: 'boom' }` to the active request, and a later `evaluate` delivers an error too
  - dispose: `dispose()` sets `terminated` and later `emit` calls change nothing

  ```ts
  export interface Evaluator {
    setFen(fen: string): void

  }

  ```

- [ ] **Step 1: Write the failing tests** (Vitest fake timers, `FakeTransport` from `makeTransport`):
  - initial state is `{ status: 'idle' }` and `makeTransport` is not called
  - a finished-game FEN gives `done` with a `final` evaluation immediately and never calls `makeTransport`
  - a normal FEN: nothing is posted before 150 ms; after 150 ms `makeTransport` is called once
  - two `setFen` calls within 150 ms evaluate only the second FEN
  - `makeTransport` throwing (for example WebAssembly missing) gives `{ status: 'error', message: <the error message> }` and does not throw out of `setFen`
  - `dispose()` clears a pending timer, terminates a created transport, and later `setFen` calls do nothing
